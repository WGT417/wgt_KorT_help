# 국어의 근거

국어 교사가 문식성·문법·문학 개론서에서 근거를 찾고, 필요할 때 OpenAI GPT-5.6 Luna로 설명과 책별 비교를 생성하는 로컬 PWA입니다.

## 실행

`start.cmd`를 실행하고 <http://localhost:8765>에 접속합니다. 서버는 `127.0.0.1`에만 바인딩합니다. 서버 창을 종료하면 앱의 검색·해설 기능도 종료됩니다.

Python 3.11 이상과 `requirements.txt`의 라이브러리가 필요합니다. 현재 컴퓨터에는 `.runtime`에 설치되어 있고, `start.ps1`은 Codex 번들 Python을 우선 사용합니다. 다른 환경에서는 `python -m pip install -r requirements.txt` 후 `python server.py`로 실행합니다.

## 자료 구성

- `개론서 파일/문식성`: 화법·작문·독서 5권
- `개론서 파일/문법`: 문법·음운·국어사 5권
- `개론서 파일/문학`: 문학·문학교육 16권
- `개론서 파일/참고자료`: 교육과정 관련 3개, 앱 검색에서는 제외
- 요약본 15개 삭제. 이동·삭제 기록은 `data/organization.json`.
- 개론서 26권 12,147페이지, 참고자료를 포함하면 29개 12,787페이지.

PDF는 자료 처리용으로만 보관합니다. 앱에는 PDF 링크·미리보기·책 선택 기능이 없습니다. 검색 영역은 문식성·문법·문학 세 가지입니다.

## 검색과 해설

1. 자동 판단은 로컬 표현 규칙으로 비교·판단·적용 질문을 판별합니다. 완전한 의도 분류기가 아니므로 사용자가 방식을 변경할 수 있습니다.
2. 원문만 검색은 OpenAI API를 호출하지 않습니다.
3. PDF 행의 좌표로 본문·여백 주석·표를 분리하고, 같은 줄의 조각은 좌우 순서로 재결합합니다. 작은 글씨의 글머리표 목록이나 칸이 나뉜 행은 표로 분류해 해당 쪽의 근거에 함께 붙입니다. 장 끝의 학습활동·연습문제는 `exercise`로 분류해 설명 근거에서 제외하고 출처 창에서만 접어 보여 줍니다. Kiwi로 띄어쓰기를 정리하되 공백 외 글자가 바뀐 결과는 채택하지 않습니다. 검색은 문단과 연속 문장을 대상으로 하며, 발췌는 문장 중간에서 끊지 않고 개념을 전개하는 문단 전체를 우선합니다. 출판사 목록·차례·깨진 도표를 일반 개념의 설명으로 내보내지 않습니다. 개념 일치·설명 표현·질문의 분류/과정 의도와 BGE-M3 벡터 색인의 의미 유사도를 함께 평가하고, 질문 낱말이 그대로 없어도 뜻이 가까운 문단을 찾습니다(아래 **뜻으로 찾기**). 책별 결과 수를 강제로 채우지 않습니다. 인용은 추출문과의 글자별 대응을 보존합니다. 벡터 색인이 없으면 이전처럼 로컬 E5 모델로 어휘 검색 후보만 재정렬합니다.
4. AI 해설은 개요를 읽는 검색 계획과 최종 설명 생성의 두 단계입니다. 처음 6페이지를 바탕으로 최대 10개 하위 주제를 검색하고, 다음 페이지의 이어지는 설명도 수집합니다. 최종 근거는 최대 28페이지·85,000자로 제한합니다. 질문과 관련 텍스트만 OpenAI에 전송하며 책 전체 파일은 전송하지 않습니다. 원문 검색 방식은 이 단계를 실행하지 않습니다.
5. 설명은 정의·분류 기준·하위 유형·예시·종합 일람표로 구조화합니다. 각 설명과 표의 행마다 제공된 발췌 ID를 선택하게 하고, 서버가 해당 20~500자의 원문 인용과 출처를 붙입니다. 서버가 존재하지 않는 출처와 원문에 없는 인용문을 걸러내고, 제외된 설명이 있으면 불완전함을 표시합니다. 인용문 존재 검사는 주장의 의미적 타당성까지 보증하지 않습니다.
6. 설명을 먼저 표시하고 참고 원문은 접어 둡니다. 출처 버튼은 해당 설명에 사용된 인용문을 먼저 열며 페이지 전체 원문도 펼칠 수 있습니다. AI 미연결 시에는 원문 검색 결과를 표시합니다. 현대 국어와 국어사·학교 문법과 개론서별 분석 체계의 차이는 구분하도록 지시합니다.
7. 관련 근거가 없으면 설명을 임의로 생성하지 않습니다.

## 뜻으로 찾기 (BGE-M3 벡터 검색)

원문 검색은 질문 낱말이 모두 들어 있는 문단만 후보로 삼았기 때문에 "사람들 앞에서 발표할 때 느끼는 두려움"처럼 용어(의사소통 불안)를 모르고 풀어 쓴 질문에는 결과가 없었습니다. 이제 개론서 문단을 다국어 임베딩 모델 **BGE-M3**(BAAI, 1024차원)로 미리 벡터화해 두고, 질문과 뜻이 가까운 문단도 함께 찾습니다. 모델과 색인은 이 컴퓨터(또는 서버)에만 있으며 검색에 OpenAI API나 외부 네트워크를 쓰지 않습니다.

- **색인 단위**: 본문·주석 문단을 문장 경계에서 40~640자 단위로 겹치지 않게 자른 청크 34,128개입니다(`passage_text.chunks`). 발췌 규칙과 같이 문장 중간에서 끊지 않고 추출문과의 글자 대응을 보존하며, 오인식 기호가 섞인 문장은 넣지 않습니다. 본문 글자의 약 70%가 들어가고, 참고문헌·시 인용·예문 목록, 오인식 의심 문장, 쪽 경계에서 잘린 문장은 빠집니다.
- **모델**: 색인은 전체 정밀도 모델(`model.onnx`, 2.3GB)로 만들고, 질문은 로컬·서버 모두 int8 모델(`model_quantized.onnx`, 570MB)로 임베딩합니다. 순수 벡터 검색으로 비교했을 때 두 질의 모델의 적중률 차이는 질문 2~3개 이내였고 int8이 두 배 빠릅니다(질문 1개 약 0.1초).
- **순위**: 어휘 검색 후보에 의미 유사도를 붙이고, 벡터 색인에서 가까운 청크 60개를 더합니다. 점수는 `코사인 유사도×100 + 어휘 점수×0.45`입니다. 뜻으로만 찾은 문단은 유사도 0.55 이상(질문 낱말이 든 문단이 하나도 없으면 0.58 이상)이어야 하고, 어휘 검색의 강등 규칙(교과서·성취기준 언급, 다른 영역 전문서, 오인식 페이지, 국어사 책)을 감점으로 받으며, 낱말이 일치하는 근거가 있을 때는 그만큼 강할 때만 함께 나옵니다. 이런 문단의 카드에는 **뜻이 가까운 문단** 표지가 붙습니다.
- **평가**: `python scripts/eval_retrieval.py`. 개념 사전 137개 항목의 확정 근거 쪽(±1쪽)을 정답으로, 개념 이름으로 묻는 질문과 이름을 쓰지 않고 풀어 쓴 질문(`scripts/eval_queries.json`)을 각각 던집니다. 정답 쪽은 한 사람이 개념 정리에 인용한 쪽이라 관련 쪽을 모두 담지 않으므로, 정밀도는 방식끼리 비교하는 용도입니다.

| 질문 방식 | 검색 | 1위 적중 | 3위 내 | 8위 내 | MRR | 정밀도 | 빈 결과 | 평균 결과 수 |
|---|---|---|---|---|---|---|---|---|
| 개념 이름 | 기존(어휘+E5) | 0.69 | 0.83 | 0.86 | 0.76 | 0.51 | 0.08 | 5.9 |
| 개념 이름 | 벡터만 | 0.64 | 0.86 | 0.96 | 0.76 | 0.49 | 0 | 8 |
| 개념 이름 | **혼합(현재)** | **0.74** | **0.88** | 0.94 | **0.82** | **0.61** | 0.01 | 5.9 |
| 풀어 쓴 질문 | 기존(어휘+E5) | 0.17 | 0.23 | 0.24 | 0.20 | 0.17 | 0.39 | 1.9 |
| 풀어 쓴 질문 | 벡터만 | 0.42 | 0.69 | 0.86 | 0.58 | 0.33 | 0 | 8 |
| 풀어 쓴 질문 | **혼합(현재)** | **0.45** | 0.66 | 0.82 | 0.58 | **0.37** | 0 | 6.7 |

기존 검색이 8위 안에서 찾던 질문을 혼합 검색이 놓친 경우는 없습니다. 풀어 쓴 질문 중 40개는 기존 검색이 찾지 못하던 정답 쪽을 1위로 올렸습니다. 검색 한 번은 이 노트북에서 평균 1.3초에서 1.7초로 늘었고, 서버를 시작할 때 모델과 색인을 올리는 데 약 4초가 걸립니다.

- **한계**: 엉뚱한 질문에도 결과가 나올 수 있습니다("오늘 점심 메뉴 추천해 줘"는 1건). 오인식 검출기가 잡지 못한 한글형 오인식은 뜻으로 찾은 발췌에도 그대로 보입니다. 문단을 다시 처리(`rebuild_passages.py`)하면 `build_vectors.py`를 다시 실행해야 하며, 본문 처리 버전(`VERSION`)이 바뀌면 다시 만들 때까지 뜻으로 찾기가 꺼지고 어휘 검색만 동작합니다.
- **색인 만들기**: `python scripts/download_bge_m3.py --full`로 모델을 받고 `python scripts/build_vectors.py`를 실행합니다. OpenVINO가 설치되어 있으면(`python -m pip install openvino`) Intel 내장 GPU를 써서 이 노트북(Core 5 120U)에서 약 1시간 30분 걸렸고, 없으면 CPU로 돌아가 10시간 이상 걸립니다. 벡터는 청크 문장의 해시로 저장해 중단해도 이어서 만들고, 문단이 바뀐 청크만 다시 임베딩합니다. 질의만 할 컴퓨터는 `--full` 없이 받거나 `pull-data`로 받습니다.
- **파일**: `data/models/bge-m3/`(토크나이저, int8 모델, 전체 정밀도 모델), `data/vectors/bge-m3.sqlite3`(청크·벡터 121MB). 전체 정밀도 모델은 색인 생성 전용이라 버킷 동기화와 배포 이미지에서 제외합니다.

## 글자 오인식 처리

`python scripts/audit_glyphs.py`가 본문·표·주석 조각 전체를 훑어 두 가지를 기록합니다(`data/glyph-audit.json`).

- **기호 오인식**: 한글 획을 그리스 문자(ι·α·λ·η…)나 통화 기호, 역슬래시로 읽은 경우. 이런 기호가 든 문장은 오인식 의심 문장으로 취급해 카드 발췌와 AI 근거에서 제외합니다. 출처 창에서는 문단을 통째로 보여 주되 해당 문장을 흐리게 표시하고 "오인식 의심" 표지를 붙입니다. 문장을 빼서 문단이 끊겨 보이던 문제를 이렇게 대신합니다.
- **한글 유사 글자 오인식**: 히↔하, 지↔자, 둥↔등, 뭇↔뜻, 볍↔법 같은 혼동. 의심 음절이 든 어절마다 교정형을 만들어 Kiwi 언어 모델 점수를 비교하고, 교정형이 말뭉치에 실제로 더 자주 나타나며 점수가 뚜렷이 오르고 실제 단어 목록에 없을 때만 규칙으로 채택합니다(`data/ocr-corrections.json`). 규칙은 어절 전체·같은 길이 치환뿐이며 **화면 표시에만** 적용합니다. 추출문, 발췌, AI 인용은 원래 글자를 유지하고, 카드와 출처 창에 교정한 낱말 수를 표시합니다.

## 찾아보기 용어 사전 (AI 미사용)

개론서 각 권의 권말 **찾아보기**를 그대로 용어 사전으로 씁니다. `python scripts/build_term_index.py`가 찾아보기 페이지의 "용어 쪽수" 항목을 읽어, 책의 쪽수 대응으로 자료 페이지를 찾고, 그 쪽(±1)에 용어가 실제로 있을 때만 남깁니다. 같은 표기의 용어는 책을 넘어 하나로 합치고, 각 쪽에서 용어를 이름 붙여 설명하는 문장을 본문 조각에서 뽑아 둡니다(`data/term-index.json`).

- 질문의 낱말(또는 이어진 두세 낱말)이 찾아보기 용어와 정확히 같을 때만 **찾아보기 카드**가 나옵니다. 카드에는 그 용어를 실은 모든 책의 쪽과 정의 문장이 책별로 나열되고, 쪽을 누르면 출처 창이 열립니다.
- 26권 중 22권에서 용어 6,261개, 책·쪽 11,742곳을 얻었고 그중 8,245곳에 정의 문장이 붙었습니다. 문법 5권만 보면 용어 2,338개입니다. 책 쪽수 대응이 확인되지 않은 책은 찾아보기 항목이 실제 쪽에 맞아떨어지는 오프셋을 자동으로 찾아 씁니다(시와 함께 배우는 시).
- 빠진 4권의 사정은 다릅니다. 고전산문교육론은 권말에 찾아보기가 없습니다(저자 소개로 끝남). 한국문학강의는 인명 찾아보기만 있어 용어 사전으로 쓸 수 없습니다. 교과서 시 정본 해설과 고전시가작품론은 권말 목록이 이미지로만 남아 있어 내장 텍스트와 Tesseract 300dpi 재인식 모두 판독 불가였고, 고전시가작품론의 것은 용어가 아니라 '인용 작품 목록'입니다. 다시 OCR한다고 해결되지 않으며, 필요하면 사람이 옮겨 적어야 합니다.
- 학교 문법 용어와 개론서 용어가 다를 때는 `retrieval.py`의 별칭 목록으로 잇습니다. 관형절↔관형사절, 관계 관형절↔관계 관형사절·관계절, 재귀 대명사↔재귀칭, 안은문장↔내포문, 된소리되기↔경음화 등이며, 찾아보기 카드는 두 이름을 한 카드로 합쳐 보여 줍니다.
- 정의 문장은 책 문장을 그대로 옮긴 것이고, 없는 쪽은 "정의 문장을 찾지 못함"으로 표시합니다. 사람이 쓴 개념 정리(아래)와 함께 표시되며 서로를 대체하지 않습니다.

## 개념 정리 (AI 미사용)

`concepts/*.json`에 미리 작성한 개념 항목을 두고, 질문에 개념 이름이나 별칭이 들어 있으면 원문 검색 결과 위에 **개념 정리** 카드를 고정 출력합니다. 런타임에 AI를 호출하지 않으며, 질문에 없는 개념을 추측해 보여 주지 않습니다.

- 카드는 탭 없이 한 편의 정리 문서로 보여 줍니다. 요약 문장, 번호가 붙은 절(개념과 성립 원리, 어미 유형과 용례, 종속과의 구별, 판별 시 유의점, 개론서별 체계 차이 등), 절 안의 항목과 하위 항목·용례, 맨 아래 개론서 근거 쪽 순서입니다.
- 항목 구조(schema 2): `summary`, `sections[{heading, intro?, items[{label?, text?, sub?, examples?, refs?}]}]`, `sources`, `review`. 본문에는 `**강조**`와 `` `어미` `` 두 가지 표시만 씁니다. `refs`는 `sources`의 순번이며 해당 항목 옆에 쪽 단추로 붙습니다. schema 1 항목(`explanation` 문단)은 요약과 문단만 표시하고, `steps`·`examples`·`counter_examples`·`common_errors`는 남아 있어도 화면에 내지 않습니다.
- `문법.json`의 49개 항목과 `문법-보강.json`은 모두 schema 2이며, 우리말문법론·한국어문법총론 1·한국어표준문법·국어음운론 강의·쉽게 풀어 쓴 국어사 개론의 해당 쪽을 읽고 썼습니다.
- 근거 쪽은 책 제목과 자료 페이지로 적고, 앱이 서재의 쪽 번호와 연결해 출처 창으로 엽니다. `status`가 `verified`면 본문을 읽고 확정한 쪽, `candidate`면 용어 일치로 찾은 후보 쪽입니다.
- `review.status`가 `reviewed`가 되기 전까지 카드에 **초안 · 검수 전**을 표시합니다. 문법 49개·문식성 53개·문학 33개 항목은 모두 이 서재의 개론서 본문을 읽고 교사·임용 관점으로 작성한 초안입니다. 문학 항목은 시 10·소설 8·고전소설 5·고전시가 3·구비문학 1·문학교육 6개로, 문식성 항목은 화법 19·작문 16·독서 18개로 나뉩니다.
- 검사: `python scripts/check_concepts.py`. 구조, 최소 분량, 연결 개념, 근거 쪽의 존재를 확인하며 테스트에서도 실행합니다.
- 문법 항목 재이식: `python scripts/port_grammar_concepts.py <export.json> <references.json>`.

## API 키

전체 자료 재처리는 `python scripts/rebuild_passages.py`, 검사는 `python scripts/audit_passages.py`입니다. `data/full-text-audit.json`은 26권 12,147페이지의 처리 누락·공백 외 글자 변경·문단 유형과 문법/독서/작문/문학 35개 질의의 실제 발췌·순위·시간을 기록합니다. 자동 전수 검사는 모든 OCR 글자의 정확성이나 모든 질문의 관련성을 보증하는 수동 검수가 아닙니다.

본문 처리 구현은 `text_pipeline.py`와 `passage_text.py`, 검색은 `retrieval.py`와 `passage_search.py`, 뜻으로 찾기는 `vector_search.py`(색인 생성 `scripts/build_vectors.py`), 벡터 색인이 없을 때의 로컬 의미 비교는 `local_semantics.py`입니다. 오인식 의심 문장은 대표 발췌에서 제외하며, 원래 추출문은 출처 창에서 열 수 있습니다. 띄어쓰기 자동 정리는 글자 오인식 교정과 별개입니다.

앱 우측 상단의 **연결 설정**에 직접 입력합니다. 브라우저는 localhost 서버로만 키를 보내고 입력란을 즉시 비웁니다. 키는 이 컴퓨터의 .env 파일에 저장하며 다음 실행부터 자동 연결합니다. API 응답·URL·로그·브라우저 저장소·서비스워커 캐시에 넣지 않습니다. 연결 설정의 저장된 키 삭제 버튼으로 제거할 수 있습니다. 실제 API 사용 가능 여부는 첫 해설 요청에서 확인합니다.

선택적으로 `.env.example`을 `.env`로 복사해 로컬 파일에 설정할 수도 있습니다. 이 방식은 디스크에 키가 남습니다. `.env`는 Git 제외 대상이고 웹 서버가 제공하지 않습니다. 공개 서버에서는 이 파일을 읽지 않으며 화면의 키 입력도 비활성화됩니다(아래 공개 배포 참고).

`.env`는 저장할 때 Windows에서 현재 사용자·SYSTEM·관리자만 접근하도록 ACL을 제한합니다. 키는 여전히 로컬 디스크와 실행 중인 서버 메모리에 존재하므로, 해당 계정이나 관리자 권한이 침해된 상황까지 방어하지는 못합니다.

## 공개 배포 (Firebase Hosting + Cloud Run + Firestore)

로컬 실행(`start.cmd`)과 공개 서버는 같은 코드이며, 환경변수 `PUBLIC=1`(Dockerfile이 설정)일 때만 공개 모드로 동작합니다.

- **공개 모드의 차이**: 모든 주소에 바인딩하고 localhost Host 검사를 끕니다. POST는 `Sec-Fetch-Site: same-origin`이거나 Origin의 호스트가 요청의 Host·`X-Forwarded-Host`·`ALLOWED_HOSTS`(쉼표 구분) 중 하나와 같을 때만 허용합니다. `/api/key`는 404를 돌려주고 키는 환경변수 `OPENAI_API_KEY`에서만 읽습니다. `.env` 파일은 읽지 않습니다. 쪽수 대조·재OCR은 관리자 전용입니다.
- **로그인 없음, 하루 3회**: AI 해설이 필요한 요청은 방문자 쿠키(`__session`, 1년. Firebase Hosting이 Cloud Run으로 넘겨 주는 유일한 쿠키 이름) 기준 하루 3회, IP 기준 15회, 서버 전체 300회까지 허용합니다(`DAILY_PER_VISITOR`·`DAILY_PER_IP`·`DAILY_TOTAL`로 조정). 한국 시각 자정에 초기화됩니다. 초과하면 해설 없이 원문 검색·개념 정리·찾아보기 결과만 돌려주고 안내문을 붙입니다. 해설 생성이 실패하면 횟수를 돌려줍니다. 쿠키 삭제나 IP 변경으로 개인 제한은 우회할 수 있으므로 전체 상한과 OpenAI 프로젝트의 월 예산 한도가 실제 방어선입니다.
- **횟수 저장소**: `QUOTA_BACKEND`가 `firestore`(공개 모드 기본)면 Google Cloud Firestore에 `quota_visitor`·`quota_ip`·`quota_daily` 컬렉션으로 기록합니다. Cloud Run에서는 별도 키 파일 없이 기본 서비스 계정으로 접근합니다. 문서에는 `expires` 필드가 있어 Firestore TTL 정책을 걸면 자동 삭제됩니다. Firestore에 연결하지 못하면 해설을 거부하고 검색만 제공합니다(fail closed). `memory`는 프로세스 메모리에만 세는 시험용, `none`(로컬 기본)은 세지 않습니다.
- **관리자**: 환경변수 `ADMIN_TOKEN`과 같은 값을 `X-Admin-Token` 헤더로 보내면 횟수 제한 없이 해설을 생성하고 쪽수 대조도 할 수 있습니다. 화면 우측 상단 **관리자** 단추에서 토큰을 입력하면 그 브라우저의 localStorage에만 저장합니다. 토큰이 틀리면 저장하지 않습니다.
- **자료는 버킷에, 배포는 어디서나**: `data/`(발췌 DB 276MB, BGE-M3 질의 모델 570MB·벡터 색인 121MB, E5 모델 137MB, 쪽별 원문 53MB)는 git에 없고 같은 프로젝트의 Cloud Storage 버킷에 둡니다. `python scripts/cloud.py push-data`로 올리고, 다른 컴퓨터에서는 `git pull` 뒤 `pull-data`로 받습니다. 배포(`deploy`)는 코드만 올리고 Cloud Build가 버킷에서 `data/`를 받아 이미지에 넣으므로(`cloudbuild.yaml`) 자료가 없는 컴퓨터에서도 됩니다. 설정은 `deploy.json`(프로젝트 ID·리전·서비스명·버킷명)입니다. `개론서 파일/`, `.runtime/`, `.env`, `tests/`는 이미지에 들어가지 않습니다. 개념 JSON도 서버가 읽으므로 개념을 고치면 다시 `deploy`해야 합니다.
- **명령**: 프로젝트마다 한 번 `python scripts/cloud.py setup`(API 활성화, 버킷·이미지 저장소 생성). 첫 배포는 `python scripts/cloud.py deploy --openai-key ... --admin-token ...`, 이후에는 `python scripts/cloud.py deploy`만 실행하면 이전 환경변수를 유지합니다. Firebase Hosting은 `dist/`를 서비스하고 `/api/**`를 이 Cloud Run 서비스로 넘깁니다(`firebase.json`, `firebase deploy --only hosting`).
- **다른 컴퓨터에서 이어서 작업**: `git clone` 또는 `pull` → `python -m pip install -r requirements.txt` → `gcloud init`과 `firebase login`(컴퓨터마다 한 번) → 로컬 실행이 필요하면 `python scripts/cloud.py pull-data`. 배포만 할 거면 `pull-data` 없이 `deploy`가 됩니다. 자료를 다시 처리한 컴퓨터에서는 `push-data`로 버킷을 갱신합니다.
- **메모리**: 서버는 시작하면서 BGE-M3 int8 질의 모델(약 870MB)과 벡터 색인(약 140MB)을 올립니다. 이 컴퓨터에서 검색 한 번을 마친 프로세스의 실사용이 약 1.1GB여서 `deploy.json`의 `2Gi` 안에 들어가지만, 동시 요청이 몰릴 때의 여유는 Cloud Run에서 아직 확인하지 않았습니다. 메모리 초과로 인스턴스가 재시작되면 `memory`를 `4Gi`로 올리세요.
- **남는 위험**: 방문자는 키 문자열을 볼 수 없지만 하루 3회 범위에서 키의 크레딧을 씁니다. 배포 키는 이 앱 전용 OpenAI 프로젝트에서 발급하고 예산 한도를 걸어 두세요. 감사 로그는 Cloud Run 로그의 오류 줄 외에는 남기지 않습니다.
- `.env`, `data/`, `개론서 파일/`은 `.gitignore`에서 제외합니다. 새 저장소를 만든 뒤 첫 커밋 전 실제 스테이징 목록과 비밀 탐지 결과를 다시 확인해야 합니다.

자동 테스트는 OpenAI 응답을 대체하여 검색 확장, 구조화된 설명·표, 인용 검사, 검색 시 API 미호출, 오류 처리를 검증합니다. 8766 고정 응답 화면은 폐기했습니다. 이전 주소는 실제 앱(8765)으로 이동하며 질문 API는 410을 반환합니다. `python scripts/verify_explanation.py --live`는 실제 질문·관련 원문을 기존 설정된 OpenAI API로 보내는 별도 검증입니다. 실제 해설 검증은 사용자가 허용한 대표 질문과 관련 발췌문에 한해 실행하며, `data/explanation-verification-*.json`에 질문별 결과를 저장합니다. 이 파일을 서버의 답변으로 재생하지 않습니다.

## OCR와 쪽수 정확도

기존 PDF의 OCR 텍스트를 페이지별로 추출해 `data/text/<book-id>/<PDF페이지>.json`에 보존합니다. 빈 텍스트 또는 글자가 적은 페이지는 Tesseract 한국어·영어 OCR로 보완하고 `.ocr.json`으로 별도 저장합니다. 글자 수는 충분하지만 내장 텍스트가 심하게 깨진 페이지는 `scripts/repair_noisy_ocr.py`가 Kiwi 언어 모델의 글자당 점수로 가려내어 300dpi로 다시 OCR하고, 점수가 뚜렷이 높아질 때만 새 텍스트를 채택합니다. 이때 행 좌표도 함께 저장해 문단 분리에 씁니다. 다시 OCR한 뒤에도 점수가 낮은 페이지(표·시·음운 기호·앞표지 등 산문이 아닌 쪽 포함)는 `quality='review'`로 두어 검색 순위를 낮추고 화면에 원문 이미지 대조가 필요하다고 표시합니다. 점수는 `page_quality` 표에 남기며 `--remark`로 OCR 없이 기준만 다시 적용할 수 있습니다. SQLite에는 현재 검색할 텍스트와 추출 방식이 저장됩니다. 원본 PDF는 수정하지 않습니다.

책 쪽수는 페이지 여백에서 직접 읽은 숫자가 앞뒤 페이지 번호와 일치할 때 `sequence`, 사람이 원문과 대조했을 때 `manual`로 관리합니다. 확인되지 않은 경우 **자료 N페이지 · 책 쪽수 미확인**으로 표시하며 PDF 순번을 책 쪽수로 바꿔 쓰지 않습니다. 전체 페이지의 OCR 교정·인쇄 쪽수 검수는 완료를 보장하지 않습니다. 옛한글, 음운 기호, 표, 각주, 다단 편집은 특히 오인식이 있을 수 있습니다.

재처리 명령:

```powershell
python scripts/index_library.py
python scripts/repair_ocr.py
python scripts/repair_noisy_ocr.py --workers 8
python scripts/rebuild_passages.py
python scripts/download_local_search_model.py
python scripts/download_bge_m3.py --full
python scripts/build_vectors.py
python scripts/eval_retrieval.py
python scripts/audit_passages.py
python -m unittest discover -s tests -v
```

인덱서는 중단 지점에서 재개합니다. 현재는 파일 경로 기준으로 문서를 식별하므로 기존 PDF를 교체하거나 이름을 바꿀 때 자동 갱신은 지원하지 않습니다. 백업 후 재색인 절차를 별도로 수행해야 합니다. 원본 체크섬은 책별로 저장합니다.
