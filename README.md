# 국어의 근거

국어 교사가 문식성·문법·문학 개론서에서 근거를 찾고, 필요할 때 OpenAI GPT-5.6 Luna로 설명과 책별 비교를 생성하는 로컬 PWA입니다.

## 실행

`start.cmd`를 실행하고 <http://localhost:8765>에 접속합니다. 서버는 `127.0.0.1`에만 바인딩합니다. 서버 창을 종료하면 앱의 검색·해설 기능도 종료됩니다.

Python 3.11 이상과 `requirements.txt`의 라이브러리가 필요합니다. 현재 컴퓨터에는 `.runtime`에 설치되어 있고, `start.ps1`은 Codex 번들 Python을 우선 사용합니다. 다른 환경에서는 `python -m pip install -r requirements.txt` 후 `python server.py`로 실행합니다.

## 자료 구성

- `개론서 파일/문식성`: 화법·작문·독서 5권
- `개론서 파일/문법`: 문법·음운·국어사 5권
- `개론서 파일/문학`: 문학·문학교육 16권
- `개론서 파일/참고자료`: 교육과정 관련 3개, 앱 검색에서는 제외
- 요약본 15개 삭제. 이동·삭제 기록은 `data/organization.json`.
- 개론서 26권 12,147페이지, 참고자료를 포함하면 29개 12,787페이지.

PDF는 자료 처리용으로만 보관합니다. 앱에는 PDF 링크·미리보기·책 선택 기능이 없습니다. 검색 영역은 문식성·문법·문학 세 가지입니다.

## 검색과 해설

1. 답변 방식은 **원문 검색(AI 활용 X)**과 **AI 활용 해설** 둘 중 하나를 직접 고릅니다. 서버가 질문의 의도를 짐작하지 않으며, 기본값은 원문 검색입니다.
2. 원문 검색은 OpenAI API를 호출하지 않고 하루 해설 횟수도 쓰지 않습니다. 검색 결과 아래의 **이 개념 해설 보기** 단추로 같은 질문을 AI 해설로 넘길 수 있습니다.
3. PDF 행의 좌표로 본문·여백 주석·표를 분리하고, 같은 줄의 조각은 좌우 순서로 재결합합니다. 작은 글씨의 글머리표 목록이나 칸이 나뉜 행은 표로 분류해 해당 쪽의 근거에 함께 붙입니다. 장 끝의 학습활동·연습문제는 `exercise`로 분류해 설명 근거에서 제외하고 출처 창에서만 접어 보여 줍니다. Kiwi로 띄어쓰기를 정리하되 공백 외 글자가 바뀐 결과는 채택하지 않습니다. 검색은 문단과 연속 문장을 대상으로 하며, 발췌는 문장 중간에서 끊지 않고 개념을 전개하는 문단 전체를 우선합니다. 출판사 목록·차례·깨진 도표를 일반 개념의 설명으로 내보내지 않습니다. 개념 일치·설명 표현·질문의 분류/과정 의도와 BGE-M3 벡터 색인의 의미 유사도를 함께 평가하고, 질문 낱말이 그대로 없어도 뜻이 가까운 문단을 찾습니다(아래 **뜻으로 찾기**). 책별 결과 수를 강제로 채우지 않습니다. 인용은 추출문과의 글자별 대응을 보존합니다. 벡터 색인이 없으면 이전처럼 로컬 E5 모델로 어휘 검색 후보만 재정렬합니다.
4. AI 해설은 개요를 읽는 검색 계획과 최종 설명 생성의 두 단계입니다. 처음 6페이지를 바탕으로 최대 10개 하위 주제를 검색하고, 다음 페이지의 이어지는 설명도 수집합니다. 최종 근거는 최대 28페이지·85,000자로 제한합니다. 질문과 관련 텍스트만 OpenAI에 전송하며 책 전체 파일은 전송하지 않습니다. 원문 검색 방식은 이 단계를 실행하지 않습니다.
5. 설명은 정의·분류 기준·하위 유형·예시·종합 일람표로 구조화합니다. 각 설명과 표의 행마다 제공된 발췌 ID를 선택하게 하고, 서버가 해당 20~500자의 원문 인용과 출처를 붙입니다. 서버가 존재하지 않는 출처와 원문에 없는 인용문을 걸러내고, 제외된 설명이 있으면 불완전함을 표시합니다. 인용문 존재 검사는 주장의 의미적 타당성까지 보증하지 않습니다.
6. 설명을 먼저 표시하고 참고 원문은 접어 둡니다. 출처 버튼은 해당 설명에 사용된 인용문을 먼저 열며 페이지 전체 원문도 펼칠 수 있습니다. AI 미연결 시에는 원문 검색 결과를 표시합니다. 현대 국어와 국어사·학교 문법과 개론서별 분석 체계의 차이는 구분하도록 지시합니다.
7. 관련 근거가 없으면 설명을 임의로 생성하지 않습니다.

## 뜻으로 찾기 (BGE-M3 벡터 검색)

원문 검색은 질문 낱말이 모두 들어 있는 문단만 후보로 삼았기 때문에 "사람들 앞에서 발표할 때 느끼는 두려움"처럼 용어(의사소통 불안)를 모르고 풀어 쓴 질문에는 결과가 없었습니다. 이제 개론서 문단을 다국어 임베딩 모델 **BGE-M3**(BAAI, 1024차원)로 미리 벡터화해 두고, 질문과 뜻이 가까운 문단도 함께 찾습니다. 모델과 색인은 이 컴퓨터(또는 서버)에만 있으며 검색에 OpenAI API나 외부 네트워크를 쓰지 않습니다.

- **색인 단위**: 본문·주석 문단을 문장 경계에서 40~640자 단위로 겹치지 않게 자른 청크 34,128개입니다(`passage_text.chunks`). 발췌 규칙과 같이 문장 중간에서 끊지 않고 추출문과의 글자 대응을 보존하며, 오인식 기호가 섞인 문장은 넣지 않습니다. 본문 글자의 약 70%가 들어가고, 참고문헌·시 인용·예문 목록, 오인식 의심 문장, 쪽 경계에서 잘린 문장은 빠집니다.
- **모델**: 색인은 전체 정밀도 모델(`model.onnx`, 2.3GB)로 만들고, 질문은 로컬·서버 모두 int8 모델(`model_quantized.onnx`, 570MB)로 임베딩합니다. 순수 벡터 검색으로 비교했을 때 두 질의 모델의 적중률 차이는 질문 2~3개 이내였고 int8이 두 배 빠릅니다(질문 1개 약 0.1초).
- **순위**: 어휘 검색 후보에 의미 유사도를 붙이고, 벡터 색인에서 가까운 청크 60개를 더합니다. 점수는 `코사인 유사도×100 + 어휘 점수×0.45`입니다. 뜻으로만 찾은 문단은 유사도 0.55 이상(질문 낱말이 든 문단이 하나도 없으면 0.58 이상)이어야 하고, 어휘 검색의 강등 규칙(교과서·성취기준 언급, 다른 영역 전문서, 오인식 페이지, 국어사 책)을 감점으로 받으며, 낱말이 일치하는 근거가 있을 때는 그만큼 강할 때만 함께 나옵니다. 이런 문단의 카드에는 **뜻이 가까운 문단** 표지가 붙습니다.
- **평가**: `python scripts/eval_retrieval.py`. 개념 사전 137개 항목의 확정 근거 쪽(±1쪽)을 정답으로, 개념 이름으로 묻는 질문과 이름을 쓰지 않고 풀어 쓴 질문(`scripts/eval_queries.json`)을 각각 던집니다. 정답 쪽은 한 사람이 개념 정리에 인용한 쪽이라 관련 쪽을 모두 담지 않으므로, 정밀도는 방식끼리 비교하는 용도입니다.

| 질문 방식 | 검색 | 1위 적중 | 3위 내 | 8위 내 | MRR | 정밀도 | 빈 결과 | 평균 결과 수 |
|---|---|---|---|---|---|---|---|---|
| 개념 이름 | 기존(어휘+E5) | 0.69 | 0.83 | 0.86 | 0.76 | 0.51 | 0.08 | 5.9 |
| 개념 이름 | 벡터만 | 0.64 | 0.86 | 0.96 | 0.76 | 0.49 | 0 | 8 |
| 개념 이름 | **혼합(현재)** | **0.74** | **0.88** | 0.94 | **0.82** | **0.61** | 0.01 | 5.9 |
| 풀어 쓴 질문 | 기존(어휘+E5) | 0.17 | 0.23 | 0.24 | 0.20 | 0.17 | 0.39 | 1.9 |
| 풀어 쓴 질문 | 벡터만 | 0.42 | 0.69 | 0.86 | 0.58 | 0.33 | 0 | 8 |
| 풀어 쓴 질문 | **혼합(현재)** | **0.45** | 0.66 | 0.82 | 0.58 | **0.37** | 0 | 6.7 |

기존 검색이 8위 안에서 찾던 질문을 혼합 검색이 놓친 경우는 없습니다. 풀어 쓴 질문 중 40개는 기존 검색이 찾지 못하던 정답 쪽을 1위로 올렸습니다. 검색 한 번은 이 노트북에서 평균 1.3초에서 1.7초로 늘었고, 서버를 시작할 때 모델과 색인을 올리는 데 약 4초가 걸립니다.

- **한계**: 엉뚱한 질문에도 결과가 나올 수 있습니다("오늘 점심 메뉴 추천해 줘"는 1건). 오인식 검출기가 잡지 못한 한글형 오인식은 뜻으로 찾은 발췌에도 그대로 보입니다. 문단을 다시 처리(`rebuild_passages.py`)하면 `build_vectors.py`를 다시 실행해야 하며, 본문 처리 버전(`VERSION`)이 바뀌면 다시 만들 때까지 뜻으로 찾기가 꺼지고 어휘 검색만 동작합니다.
- **색인 만들기**: `python scripts/download_bge_m3.py --full`로 모델을 받고 `python scripts/build_vectors.py`를 실행합니다. OpenVINO가 설치되어 있으면(`python -m pip install openvino`) Intel 내장 GPU를 써서 이 노트북(Core 5 120U)에서 약 1시간 30분 걸렸고, 없으면 CPU로 돌아가 10시간 이상 걸립니다. 벡터는 청크 문장의 해시로 저장해 중단해도 이어서 만들고, 문단이 바뀐 청크만 다시 임베딩합니다. 질의만 할 컴퓨터는 `--full` 없이 받거나 `pull-data`로 받습니다.
- **파일**: `data/models/bge-m3/`(토크나이저, int8 모델, 전체 정밀도 모델), `data/vectors/bge-m3.sqlite3`(청크·벡터 121MB). 전체 정밀도 모델은 색인 생성 전용이라 버킷 동기화와 배포 이미지에서 제외합니다.

## 글자 오인식 처리

`python scripts/audit_glyphs.py`가 본문·표·주석 조각 전체를 훑어 두 가지를 기록합니다(`data/glyph-audit.json`).

- **기호 오인식**: 한글 획을 그리스 문자(ι·α·λ·η…)나 통화 기호, 역슬래시로 읽은 경우. 이런 기호가 든 문장은 오인식 의심 문장으로 취급해 카드 발췌와 AI 근거에서 제외합니다. 출처 창에서는 문단을 통째로 보여 주되 해당 문장을 흐리게 표시하고 "오인식 의심" 표지를 붙입니다. 문장을 빼서 문단이 끊겨 보이던 문제를 이렇게 대신합니다.
- **한글 유사 글자 오인식**: 히↔하, 지↔자, 둥↔등, 뭇↔뜻, 볍↔법 같은 혼동. 의심 음절이 든 어절마다 교정형을 만들어 Kiwi 언어 모델 점수를 비교하고, 교정형이 말뭉치에 실제로 더 자주 나타나며 점수가 뚜렷이 오르고 실제 단어 목록에 없을 때만 규칙으로 채택합니다(`data/ocr-corrections.json`). 규칙은 어절 전체·같은 길이 치환뿐이며 **화면 표시에만** 적용합니다. 추출문, 발췌, AI 인용은 원래 글자를 유지하고, 카드와 출처 창에 교정한 낱말 수를 표시합니다. 규칙 1,665개가 5,272곳을 덮습니다.
  - **된소리로 읽은 예사소리는 꽁→공 하나만 둡니다.** "꽁기"(공기)를 보고 ㄲ·ㄸ·ㅃ·ㅆ·ㅉ 전부를 혼동 짝으로 넣어 보았더니 이 서재에서는 통하지 않습니다. 문법·음운론 책은 된소리를 **설명 대상으로** 찍어 두고(국적[국쩍], 닿소[다쏘], 등-불[등뿔], 돋보기→[돋뽀기], 지+어도→[쩌도]), 문학 책은 방언과 옛 표기를 인용합니다("뻐스 길 삼백 리", 임꺽정, "궁글 뿔고"). 쩍·썽·쩌·쭈·쏘·뿔·뿐·씬·뻐·뽀·뜸으로 통과한 교정 56개를 전부 읽어 보니 서른 개 가까이가 틀렸습니다("용언 구뿐 아니라"의 구뿐→구분, "눈 썽과 입가"의 썽과→성과, "찍히고 찍히고" 옆의 쩍힌→적힌). 책별로 가르는 장치 없이는 다시 열지 마십시오.
- **각주 번호·쉼표 오인식**: 위첨자 각주 번호가 엉뚱한 글자나 숫자로 읽히거나 쉼표가 1로 읽힌 경우를 원문 글자층의 붙어 쓰임으로 가려 **화면 표시에서만** 고칩니다(`text_pipeline.note_marks`, `tidy_display`). ① 마침표 바로 뒤에 붙은 한 글자가 문장을 시작하는 낱말(즉·이·그·또·표·시…)이 아닐 때("한다.쩌 (122)의"), ② "다" 뒤의 한두 자리 숫자("있다46 남의", "구분한다 12 단모음은", "것이다 15) 이런")는 위첨자가 앞 마침표까지 삼킨 자리이므로 숫자를 **마침표로 되돌립니다**("있다. 남의"). 쉼표에 붙어 l·I로 읽힌 번호("않으며，l7 보조")와 ③ 어미·조사에 붙은 숫자("나타나며70 격조사"), ④ 번호 붙은 제목 끝의 숫자("관형사절을안은문장39")는 지우고, "있고1 그것이"처럼 고·로·며·면·서·데 뒤에 붙은 1은 쉼표로 되돌립니다. 뒤 낱말이 년·학년·인칭·품사·번처럼 무언가를 세는 말이면("2 학년과", "2 번처럼", "9품사") 숫자로 둡니다. 전체 본문·주석에서 각주 번호 150곳을 지우고 마침표 768곳, 쉼표 302곳을 되돌리며, 규칙별 표본(②60개+45개, ③60개)을 읽었을 때 잘못 지운 것은 각 한 곳이었고(②의 45개 표본에서는 유하의 시 제목 "압구정동에 가야 한다 6") 그 경우도 목록에 추가했습니다. 지우거나 고친 개수는 오인식 교정 수에 더합니다. 주석 칸 첫머리의 각주 번호는 줄바꿈으로 잘린 낱말("허 웅")과 구별되지 않아 그대로 둡니다.
- **책이 본문에 끼워 둔 안내 표시**: 한국어표준문법은 문장과 문장 사이에 딸린 적용 상자를 "적용4"로, 우리말문법론은 권말 덧붙임을 "[덧붙임 1]."로 가리킵니다. 글자층에서는 이 표시가 본문 한가운데 그대로 들어와 있어 각주 번호와 똑같이 **화면에서만** 지웁니다(`text_pipeline.callout_marks`). 문장이 끝난 자리에 있고 뒤에 새 문장이나 문단 끝이 올 때만 지우며, 문장이 표시를 읽고 지나가면("[덧붙임 2]에서 언급한", "제13장 [덧붙임 5]를 보라", "[덧붙임 11] 에서") 그대로 둡니다. 괄호와 번호는 글자층에서 자주 깨져 있으므로("[덧붙임 8J.", "[덧붙임 1이."는 10], "적용1 0"은 적용10) 낱말 자체만 정확히 맞춰 보고 나머지는 느슨하게 봅니다. 전체에서 470곳을 지우며, 두 책 안의 표시 497곳 중 지우지 않은 것은 문장이 읽고 지나가는 경우와 "있떼덧붙임 10]"처럼 앞 글자까지 뭉개진 경우입니다. 다른 24권에서는 한 곳도 걸리지 않습니다("교수·학습 모형의 적용 1 단계", 찾아보기의 "적용 300").
- **띄어쓰기 모델이 지운 쪽의 공백**: 띄어쓰기 모델에는 줄바꿈을 지운 문단이 들어가므로, 이미 띄어 쓴 글을 다시 띄어 쓰다가 책이 찍어 둔 공백을 지웁니다("나타나기도 한다"→"나타나기도한다"). 깨진 글자 하나에 걸리면 절 전체를 붙여 버리기도 합니다(한국어표준문법 84쪽 "…은 조음 과정에서 꽁기의"→"…은조음과정에서꽁기의"). 줄 안쪽의 공백은 책의 판짜기이므로 **화면에서 되살립니다**(`text_pipeline.respace`). 다만 스캔이 낱말 가운데에 넣은 공백("보석처 럼", "소설이 다")까지 되살리면 안 되므로, `audit_glyphs.py`가 추출 원문의 줄 안쪽 어절만 세어 만든 낱말 목록 57,455개(`data/source-words.json`)에 **붙인 꼴이 들어 있으면 붙은 채로 둡니다**. 한쪽이 한 글자인 자리도 스캔의 군더더기 공백이 만드는 모양이라 모델에 맡기되, 모델이 확실히 무너진 자리(붙은 덩어리가 여덟 글자 이상)에서는 되살립니다. 찾아보기 용어를 다시 가르지는 않아 "부사격조사"는 그대로입니다. 본문·주석 전체에서 모델이 지운 공백 76,140곳 가운데 **58,590곳**(문단 19,058개)을 되살리며, 되살리지 않은 17,550곳은 말뭉치 낱말 4,940곳·한 글자 11,150곳·용어 1,460곳입니다. 붙어 버린 발췌(`unspaced`)가 383곳에서 17곳으로 줄고, 낱말 단위 교정이 닿는 자리도 늘어납니다("…에서꽁기의"는 낱말이 아니어서 고칠 수 없지만 "꽁기의"는 고칩니다).
- **라틴 낱말을 가른 공백**: 책이 용어 옆에 붙이는 원어 풀이에 공백이 끼어듭니다("자음(子音， co nsonant)", "이 형태(異形態， a llomorph)", "음운적 단어(phonologic al)"). 한글 본문 안에서 두 번 이상 나타난 라틴 낱말 1,866개(`source-words.json`의 `latin`)에 붙인 꼴이 있고 갈린 조각이 **모두 책이 쓰는 낱말은 아닐 때만** 붙입니다(`text_pipeline.join_latin`). 한 낱말이 두 번 이상 갈리기도 하므로("read i ng", "se ntenc e", "Rom a n") 잇달린 네 조각까지 긴 쪽부터 맞춰 봅니다. "in formation", "in to", "an other"처럼 조각이 모두 제 낱말이면 그대로 둡니다. 본문·주석 전체에서 848곳을 붙이며, 무작위 표본 60곳을 읽었을 때 잘못 붙인 것은 없었습니다(Question, conversion, transactional, Rimmon-Kenan, 체계문(system sentence) 등).
- **띄어쓰기 모델이 가른 용어**: Kiwi가 "관계절로"를 "관 계절로", "관형사절"을 "관형 사절", "동격"을 "동 격"으로 가르는 경우가 있습니다. 찾아보기 용어와 `text_pipeline.TERMS`의 용어마다 책 원문에서 띄어 쓴 비율을 세어(`build_term_index.py`, 관형사절 0%, 문학교육 8%, 안은문장 78%) 3% 이하로만 띄어 쓰는 용어와 용어의 앞 두 글자(동격절·동격 관형사절의 '동격') 3,565개를 `term-index.json`의 `joined`에 두고, 화면에서는 원문에 공백이 없던 자리의 공백만 지웁니다. 세 글자 이상이고 여덟 번 넘게 붙여 쓰인 용어는 띄어 쓴 읽기가 한 번뿐이면 그 한 번을 판짜기나 스캔 탓으로 보고 받습니다(체계문 21:1, 사용문 9:1). "이 형태"처럼 앞 글자가 따로 쓰이는 낱말이면 붙이지 않고, 두 글자 용어는 "동 격"처럼 한 글자씩 갈렸을 때만 붙입니다. OCR이 가른 예문 번호 "(1 23 가)"도 "(123가)"로 붙입니다.
- **한 획 틀린 용어**: "통작성"(동작성), "피통문"(피동문), "연걸어미"(연결어미), "렉스트"(텍스트), "검춘수"(김춘수)처럼 용어(세 글자 이상)와 한 글자만 다른 낱말을 전체 본문에서 찾아(`build_term_index.misreadings`) 화면에서 고칩니다. 공통 조건은 원문에서 한 덩어리로 쓰였고("부가가치는 제조업"은 '가치논제'가 아님, 줄바꿈으로만 갈린 것은 한 덩어리로 봄), 마지막 글자가 같고("형태로"는 '형태소'가 아님), Kiwi 언어 모델 점수가 6 이상 오르는 것입니다. 점수 차이가 실제 낱말(이성주의·에로스·학자 김소영, 2 이하)과 오인식(7 이상)을 갈랐습니다. **바른 표기를 무엇이 보증하느냐**는 용어의 출처에 따라 다릅니다.
  - **책의 찾아보기에서 온 용어**는 찾아보기 페이지도 같은 스캔이라 본문과 똑같이 깨져 있으므로 말뭉치가 보증해야 합니다. 바뀐 자모가 `ocr-corrections.json`에서 확인된 혼동 짝(ㅌ/ㄷ, ㅇ/ㅁ, ㅣ/ㅏ, ㅜ/ㅡ, ㅓ/ㅕ, ㅁ/ㅂ 등)이고 용어가 20배 이상 흔할 때만 받습니다.
  - **사람이 쓴 용어**(`text_pipeline.TERMS`와 `concepts/*.json`의 이름·별칭에서 뽑은 세 글자 이상 낱말 3,494개)는 둘 다 필요 없습니다. 혼동 짝이거나, **그 용어에만 있는 글자가 전체 말뭉치(한글 637만 자, 실제로 나타나는 글자 1,221자)에 단 한 번도 없으면** 됩니다. 이 스캔은 '홑'을 끝내 만들어 내지 못해 홑문장이 흩문장(33)·홀문장(12)·흘문장(6)으로만 나오고 바른 표기는 0번이라, 어떤 빈도로도 보증할 수 없는 경우입니다. 이때 용어와 한 자모 거리이면(흩/홑, 홀/홑) 언어 모델을 보지 않고, 더 멀면(흘/홑) 점수가 5 이상 올라야 합니다.
  - 찾아보기가 깨진 표기로 실은 용어는 찾아보기 항목 자체도 고친 표기로 옮깁니다. 흩문장 카드는 홑문장 카드가 되고, 깨진 표기는 `variants`에 남아 다음 빌드가 그 쪽을 다시 찾는 데 쓰입니다. 검색도 같은 표를 거꾸로 써서 "홑문장"을 물으면 쪽에 실제로 있는 흩문장·홀문장·흘문장까지 함께 찾습니다(`retrieval.damaged_spellings`).
  - 뽑힌 목록을 모두 읽어, 책이 실제로 쓰는 낱말과 옛 표기·인용시의 낱말 22개(퍼소나, 장형시, 등시성, 재도적, 가사문, 개안주, 상래의, "혈의 누"의 보이의, "차거운", 줄이 갈라 낱말처럼 보인 "투/가리를"·"서/정시적" 등)를 `NOT_MISREAD`로 빼고 564개(이전 260개)를 `term-index.json`의 `misread`에 둡니다. 전체 본문에서 1,396곳을 고치며(이전 397곳), 고친 수는 오인식 교정 수에 더합니다. 원문이 띄어쓰기를 통째로 잃은 자리("이루어진문장을흩문장이라고한다")는 화면 띄어쓰기를 낱말 시작으로 인정해 고치며, 그렇게 잡히는 60곳을 모두 읽었을 때 잘못 고친 것은 없었습니다. 정의 문장도 고친 글자로 찾으므로 "피통문이라 한다" 같은 정의가 새로 잡힙니다.
- **제목 줄**: 레이아웃 분석이 제목 줄을 아래 문단에 붙인 경우("7 보조용언의 의미 기능 국어의 보조용언은…")를 가려 따로 보여 줍니다(`split_heading`). 첫 줄이 짧고(24자 이하, 번호가 있으면 32자), 아래 줄의 절반보다 짧으며, 문장 끝·연결 어미·조사로 끝남·주격이나 주제 조사·짝이 안 맞는 괄호·끝의 숫자가 없을 때만 제목으로 봅니다. 전체 본문 문단 3,441곳이 해당하며, 표본 50개에서 문장을 가른 경우는 없었습니다(처음 기준은 13%가 오분리였음). 원문 카드에서는 제목이 한 줄 위에, 출처 창에서는 굵은 줄로 나오고, 정의 문장을 고를 때도 제목을 떼고 봅니다.
- **라틴어 풀이에 빨려 들어간 한글**: 두 단 편집에서 옆 칸이 본문 줄에 섞이면 "복합양식 텍스트(m뻐대표"하고 있다"처럼 괄호 안 원어 풀이 자리에 한글이 들어옵니다. 여는 괄호 뒤 로마자 한두 자에 한글이 바로 붙은 자리, 획이 콜론으로 읽힌 자리("pre:final", "a:J(l- stltuent"), 음절이 물결·삿갓 표시로 남은 자리("^~용하기도")를 오인식으로 셉니다(`passage_text.noise`). 예문 번호를 1 대신 l로 읽은 "(l다)는"과 음운론의 음절형 표기 "(V형, VC형 등)"은 모양이 같아 그대로 둡니다. 뜻으로 찾기 색인은 만들어 둔 조각을 그대로 쓰므로, 색인을 다시 만들기 전에도 이 규칙에 걸리는 조각은 결과에서 뺍니다.
- **자모를 다른 글자로 읽은 것**: 문법서는 자모를 따옴표로 불러 인용하는데("‘ㄹ’의 비음화") 이 스캔은 그 글자를 엉뚱하게 읽습니다. 어느 자모인지는 **책의 문장이 정해 줍니다** — "‘E’의 비음화는 ‘E’이 ‘L’으로 바뀌는 현상"과 "‘근’의 비음화를 가리키는 다른 용어"는 둘 다 ㄹ, "‘님, 표, 배, 口’이 양순음에 속한"은 ㅂ·ㅍ·ㅃ·ㅁ, "국어의 후음에는 ‘송’이 존재한다"는 ㅎ, "‘괴, 귀’는 이중 모음으로 발음할 수 있다"는 ㅚ·ㅟ입니다. 화면에서만 되돌립니다(`text_pipeline.read_citations`).
  - **낱말로는 쓰이지 않는 12개**는 문맥 없이 되돌립니다: E·근·己→ㄹ, L→ㄴ, 亡→ㄷ, 口→ㅁ, 人·λ→ㅅ, 。→ㅇ, 「→ㄱ, 닝→ㅂ, T→ㅜ.
  - **낱말이기도 한 8개**(님→ㅂ, 표→ㅍ, 송·동·승·종→ㅎ, 괴→ㅚ, 귀→ㅟ)는 같은 문장이 소리나 글자를 말할 때만 자모로 읽습니다(`JAMO_WORD`, `JAMO_CUE`). 만해의 ‘님’, 시경의 ‘송’, "‘눈’과 ‘매화 향기’의 대비"는 그대로 둡니다.
  - **조사가 자모 이름의 끝소리를 알려 줍니다**(`PARTICLE`, `two_way`). 모음 이름은 열린 음절이라(애·우·의) 가/를/는/와/로를, 자음 이름은 닫힌 음절이라(비읍·디귿) 이/을/은/과/으로를 취합니다. 리을만 ㄹ이라 "로"를 씁니다. 이것으로 **두 가지로 읽히는 글자 셋**이 갈립니다.
    - **H는 ㅐ 아니면 ㅂ**입니다. "‘H’와 ‘ㅔ’를 구분하지 못하고"는 ㅐ, "‘H’이 ‘ㄴ’ 앞에서 ‘ㅁ’으로 바뀌는"은 ㅂ. 91곳이 조사로 갈리고(ㅐ 69, ㅂ 22) 전부 읽어 확인했습니다. 조사가 없는 42곳은 **그대로 둡니다**.
    - **E는 ㄹ 아니면 ㄷ**(때로 ㅌ)입니다. "으로"가 오는 35곳은 ㄷ("평파열음화에 의해 ‘E’으로", 맞춤법 제7항), "로"가 오는 자리는 ㄹ입니다. 한 문장 안에서도 갈립니다 — "‘ㄹ’이 ‘ㄷ’으로 바뀐 것이 아니고 ‘ㄹ’이 ‘ㅅ’ 앞에서 탈락한 후".
    - **기는 ㄱ 아니면 명사형 어미 ‘-기’**입니다. 자음 조사를 달았을 때만 ㄱ으로 읽습니다(7곳).
  - **가리지 못하는 자리는 흔한 쪽을 유지합니다.** 리을과 디귿은 이름이 둘 다 자음으로 끝나 이/은/과로는 갈리지 않습니다. 그 156곳을 문맥 단서(불규칙·파열음·사이시옷 등)로 가르는 규칙을 만들어 전수로 읽어 보았더니, **"‘E’ 불규칙 활용"(ㄹ 불규칙)과 유성음 목록 "‘ㄴ, E, ㅁ, ㅇ’"을 ㄷ으로 읽는 등 68곳 중 10곳 가까이가 오히려 틀려** 규칙을 버렸습니다. 이 자리는 더 흔한 ㄹ로 읽으며, 표본으로 본 오류율은 4분의 1가량입니다.
  - **모음 셋은 숫자·붙임표·중괄호로 읽힙니다**(`VOWEL_GLYPH`): 1→ㅣ, -→ㅡ, }→ㅏ. "‘1’ 모음 역행 동화", "양순음 뒤에 오는 ‘-’", "단 모음 ‘}’". 그런데 같은 세 글자는 자음 목록에서 ㄱ 자리에도 나타나므로("‘ㄱ, ㄷ, ㅎ’의 구개음화"가 `‘1 , C , 동’`, 평파열음화의 "‘ㅂ, ㄷ, ㄱ’"이 `‘님， C , -，’`), **같은 따옴표 안에 자음이 하나라도 있으면 읽지 않습니다**(`consonant_list`). 소리·글자를 말하는 문장이라는 단서도 함께 요구합니다. 396곳이 걸리고 자음 목록 8곳이 걸러지며, 걸린 곳을 모두 훑었을 때 문법서 밖은 3곳뿐이었고 그중 틀린 것은 1곳입니다(따옴표가 작은따옴표로 끊긴 자리).
  - 따옴표 안은 **쉼표 목록만** 나눕니다. 공백까지 나누면 시의 "‘천만 근’", 서지의 "‘ E rinnerung’"이 자모가 됩니다. 붙임표나 괄호가 든 짧은 인용형은 통째로 읽습니다("‘- L 다’체" → "‘-ㄴ다’체").
  - **그대로 두는 것**: 」(ㅗ와 ㅢ 둘 다 모음이라 조사로 갈리지 않음), 리·디·격(각각 ‘-(으)리-’·중세 ‘-디’·격조사와 겹치고 자음 조사를 단 사례가 없거나 둘뿐임). 글자 뒤에 글자가 이어지면 낱말이므로 불어 제목 `‘L’enfer, c'est les autres’`는 손대지 않습니다.
- **어미 인용이 통째로 깨진 것**: "‘-(으)ㄴ’"이 `느(의L ’`로, "‘-(으)ㄹ’"이 `까으)2 ’`로 나옵니다. 여는 따옴표와 붙임표가 한 음절로 읽히고(느·노·니·나·내·냐·가·거·까·카·키·개·ι·←), 닫는 괄호는 "으"에 먹혀 "의"가 되며, 자모 자체는 글자나 숫자가 됩니다(L→ㄴ, 2·근·己·E→ㄹ, 口·디·0→ㅁ). 닫는 따옴표가 14자 안에 뒤따르는 자리에서만 되돌리며, 걸리는 191곳을 모두 읽어 멀쩡한 낱말을 먹은 경우가 없음을 확인했습니다("선어말 어미가 으)시-’를" → "선어말 어미 ‘-(으)시-’를"). ‘-는’이 ‘눈’으로 읽힌 자리는 어미를 열거하는 문장에서만 되돌립니다(`CITED_CUE`).
- **한자 병기와 목록 표시는 깨짐이 아님**: `話者는`, `軍律에`처럼 한자 뒤에 조사가 붙은 것은 이 책들의 정상 표기이므로, 한자 자리에 한글이 들어앉은 것만(模뼈=模倣) 깨짐으로 봅니다(`passage_text.BROKEN_GLOSS`). 원문자 ①②③은 이 스캔에서 전부 `@`로 나오는데, 줄 첫머리의 `@`는 쪽의 조판이므로 세지 않습니다. 따옴표 안의 홑 라틴 글자도 책이 일부러 쓰는 표기입니다(`명사 ‘A’와 ‘B’`, `‘C’는 자음`). 이 셋을 바로잡아 깨짐 집계가 4,625 → 3,676이 되고, 정의 문장을 고르는 검사가 덜 막혀 개념 카드의 오인식이 90장 → 67장(812장 중)으로 줄었습니다.
- **원어 풀이에 갇힌 한글**: 괄호 안 원어 풀이 가운데 한글 한두 자가 박히는 경우가 있습니다("intellectu 외 seriousness", "기능 문법(gr 없 lmar)", "텍스 틴 monomc 벼"). 이 스캔은 특히 "al"을 `외`로 읽습니다. 압축한 글자에서는 틈이 사라져 보이지 않으므로 띄어쓰기가 살아 있는 화면 글에서 검사합니다(`passage_text.STRANDED`). 로마자가 양쪽에 있으면 한글 두 자까지, 한글이 양쪽에 있으면 한 자만 오인식으로 보고, 조사는 세지 않아 "Chomsky 의 Syntactic Structures"나 "Halliday 와 Hasan 이"는 그대로 둡니다. 발췌 34,092개 중 87개가 걸립니다.
- **두 글자 용어**: `직문`(작문)처럼 두 글자 낱말은 무엇이든 명사+명사로 읽혀 언어 모델 점수가 오르지 않습니다(직문 2.99, 기준 4). 이때는 **사람이 쓴 용어 목록**(`text_pipeline.TERMS`와 `concepts/*.json`의 두 글자 이름 1,036개)이 표기를 보증합니다(`audit_glyphs.term_correction`). 깨진 형 자체가 용어가 아니고, 바뀐 음절이 이미 확인된 혼동 짝이며, 용어가 100배 이상 흔할 때만 받습니다. 후보의 모든 출현을 읽어 직문→작문, 지아→자아, 말디→말다를 받았고, 실제 낱말인 명시(名詩)·부시(부시쌈지)·치이(鴟夷子)는 제외했습니다.
- **말뭉치에 없는 낱말**: `audit_glyphs.py`가 26권에서 3회 이상 나타난 한글 어절 69,072개를 `data/corpus-words.json`에 적어 둡니다. 책들이 한 번도 되풀이하지 않는 낱말("인해돼스트기반입기", "복합g씩텍스트읽기")은 스캔이 만들어 낸 글자이므로, 그런 낱말의 비율(`text_pipeline.strange_ratio`)로 표가 읽을 수 있는 상태인지 판단합니다. 책이 드문 개념을 설명하는 문단은 책이 그 용어를 스스로 되풀이하므로 비율이 낮게 나옵니다.
- **읽을 수 없는 표**: 레이아웃은 단으로 짜인 것을 모두 표로 보기 때문에 찾아보기·참고문헌·차례·판권지와 스캔이 낱글자만 남긴 쪽도 표가 됩니다. 카드 아래 "같은 쪽의 표"에 붙이기 전에 `passage_search.readable_table`로 거릅니다. 한글이 글자의 45% 미만이거나, 책이 쓰지 않는 기호가 4%를 넘거나, "항목 쪽번호"·"(1998)"·"163-169" 모양의 칸이 30%를 넘거나, 한글 한 글자뿐인 칸이 40%를 넘거나, 단이 흐트러져 한 칸짜리 줄이 40%를 넘거나, 말뭉치에 없는 낱말이 25%를 넘으면 보여 주지 않습니다. 여기에 **말뭉치에 없는 일곱 글자 이상의 낱말**이 하나라도 있으면 거릅니다 — 일곱 글자짜리 진짜 한국어 낱말은 책이 다시 쓰는 용어이므로, 그런 낱말은 스캔이 끝내 가르지 못한 덩어리입니다("인해돼스트기반입기", "대명사장소표시", 판권지의 "지은이정재찬최인자김근호"). 반대로 좋은 표의 드문 낱말은 짧아서(레지스터, 멀티태스킹) 걸리지 않습니다. 전체 표 조각 1,561개 중 232개만 남으며(처음 기준으로는 1,210개), 빠진 것은 한글 아님 498개, 너무 짧음 419개, 칸이 흐트러짐 152개, 찾아보기·쪽번호 104개, 낱글자 칸 47개, 붙어 버린 긴 낱말 46개, 없는 낱말 42개, 기호 덩어리 20개입니다. 같은 기준을 AI 해설의 근거에도 적용합니다.
- **전각 문장부호·인용 인명**: OCR의 전각 쉼표 "，"는 화면 글꼴에서 앞에 공백이 있는 것처럼 보여("본용언 , 본용언과") 화면에서만 ","로 바꾸고, 한글 뒤 쉼표 다음에 공백이 없으면 한 칸을 둡니다. "박진 호(1998)"처럼 띄어쓰기 모델이 가른 인용 저자명은 원문이 붙여 쓴 경우 되돌립니다(성씨로 시작하는 2~4글자만, "특히굿맨(" 같은 원문 띄어쓰기 누락은 제외).

## 찾아보기 용어 사전 (AI 미사용)

개론서 각 권의 권말 **찾아보기**를 그대로 용어 사전으로 씁니다. `python scripts/build_term_index.py`가 찾아보기 페이지의 "용어 쪽수" 항목을 읽어, 책의 쪽수 대응으로 자료 페이지를 찾고, 그 쪽(±1)에 용어가 실제로 있을 때만 남깁니다. 같은 표기의 용어는 책을 넘어 하나로 합치고, 각 쪽에서 그 용어를 정의하거나 설명하는 문장을 본문 조각에서 뽑아 둡니다(`data/term-index.json`).

- 질문의 낱말(또는 이어진 두세 낱말)이 찾아보기 용어와 정확히 같을 때만 **찾아보기 카드**가 나옵니다. 카드는 그 용어를 **정의하는 문장**이 있는 쪽만 한 줄씩 보여 주고(찾아보기 쪽 → 찾아보기 밖 → 오인식 있음 순), 용어가 나오기만 하는 쪽은 맨 아래 "이 용어가 나오는 다른 쪽" 한 줄에 쪽 단추로만 모읍니다. 관형절·관형사절처럼 두 이름이 같은 쪽을 가리키면 한 번만 보여 줍니다. 쪽을 누르면 출처 창이 열립니다.
- 문장 점수(`term_index.definition_score`): "X란 …이다/…을 말한다", "…을 X라고 부른다/한다" 10, "X는 …을 말한다/가리킨다/일컫는다", "…것이 X이다" 9, "X로 불린다" 8, "X는 …이다" 7, 그 밖에 X를 주어로 한 문장 5, 그냥 언급 1입니다. **7점 이상만 카드에 문장으로 싣습니다.** 용어는 낱말 첫머리에 있어야 하고("과정에서는"의 '에서'는 조사 항목이 아님), "X는"으로 여는 문장은 앞에 일반적으로·즉·첫째 같은 말이나 번호만 올 수 있으며("가장 긴 드라마는", "단어 형성 규칙은"은 제외), 이름 붙이기 앞 낱말이 명사면 더 긴 이름의 꼬리로 봅니다("음소 분석이라고"의 '분석'). "…라 한다면", "…이라고 불러야", "…로 명명되는", "X란 그런 것이다", "…일반적이다", "…할 것이다"는 정의가 아닙니다. "동격 관형사절이란"처럼 더 긴 찾아보기 용어의 일부로 나온 경우는 2입니다. 주석 칸 문장은 3점을 깎고, 조사나 연결 어미로 시작하는(앞이 잘린) 문장, 번호 붙은 제목 줄, 예문 줄, 오인식 의심 문장은 고르지 않으며, "이를 X라 한다"는 앞 문장을 붙입니다. 끝의 인용 괄호("…의미이다(오주영, 1997).")는 문장 끝 판정에서 뺍니다.
- **이어지는 설명**: 정의 문장 뒤에 같은 문단의 문장을 최대 두 개(420자까지) 붙입니다(`with_context`). 용어를 다시 부르거나 "이는·즉·따라서·이러한"처럼 앞 문장을 받는 문장만 잇고, 예문 번호를 참조하거나("(3다)의 ‘길이’는") "다음과 같다·살펴보자"처럼 다른 곳을 가리키거나 오인식이 보이는 문장에서 멈춥니다. 앞머리의 각주 번호("13)", "21")와 "[덧붙임 7]."은 뗍니다. 처음에는 문단의 다음 문장을 조건 없이 붙였는데 표본 40개 중 주제에서 벗어난 것("빨간 장미꽃이 아름답다 하는 말은")과 예문 참조가 섞여 이 조건을 넣었습니다. 정의 1,152곳 중 409곳에 설명이 붙습니다(예: 보조용언 → "보조용언만으로는 문장이 성립하지 않으며, 보조용언은 본용언의 뒤에 와서 다양한 기능을 한다").

## 개념 정리 (AI 미사용)

`concepts/*.json`에 미리 작성한 개념 항목을 두고, 질문에 개념 이름이나 별칭이 들어 있으면 원문 검색 결과 위에 **개념 정리** 카드를 고정 출력합니다. 런타임에 AI를 호출하지 않으며, 질문에 없는 개념을 추측해 보여 주지 않습니다.

- 카드는 탭 없이 한 편의 정리 문서로 보여 줍니다. 요약 문장, 번호가 붙은 절(개념과 성립 원리, 어미 유형과 용례, 종속과의 구별, 판별 시 유의점, 개론서별 체계 차이 등), 절 안의 항목과 하위 항목·용례, 맨 아래 개론서 근거 쪽 순서입니다.
- 항목 구조(schema 2): `summary`, `sections[{heading, intro?, items[{label?, text?, sub?, examples?, refs?}]}]`, `sources`, `review`. 본문에는 `**강조**`와 `` `어미` `` 두 가지 표시만 씁니다. `refs`는 `sources`의 순번이며 해당 항목 옆에 쪽 단추로 붙습니다. schema 1 항목(`explanation` 문단)은 요약과 문단만 표시하고, `steps`·`examples`·`counter_examples`·`common_errors`는 남아 있어도 화면에 내지 않습니다.
- `문법.json`의 49개 항목과 `문법-보강.json`은 모두 schema 2이며, 우리말문법론·한국어문법총론 1·한국어표준문법·국어음운론 강의·쉽게 풀어 쓴 국어사 개론의 해당 쪽을 읽고 썼습니다.
- 근거 쪽은 책 제목과 자료 페이지로 적고, 앱이 서재의 쪽 번호와 연결해 출처 창으로 엽니다. `status`가 `verified`면 본문을 읽고 확정한 쪽, `candidate`면 용어 일치로 찾은 후보 쪽입니다.
- `review.status`가 `reviewed`가 되기 전까지 카드에 **초안 · 검수 전**을 표시합니다. 문법 49개·문식성 53개·문학 33개 항목은 모두 이 서재의 개론서 본문을 읽고 교사·임용 관점으로 작성한 초안입니다. 문학 항목은 시 10·소설 8·고전소설 5·고전시가 3·구비문학 1·문학교육 6개로, 문식성 항목은 화법 19·작문 16·독서 18개로 나뉩니다.
- 검사: `python scripts/check_concepts.py`. 구조, 최소 분량, 연결 개념, 근거 쪽의 존재를 확인하며 테스트에서도 실행합니다.
- 문법 항목 재이식: `python scripts/port_grammar_concepts.py <export.json> <references.json>`.

## API 키

화면에 실제로 나가는 글을 세는 검사는 `python scripts/audit_reading.py`입니다. 26권의 조각마다 발췌(뜻으로 찾기 색인 단위)와 같은 쪽 표를 검색 때와 똑같이 만들어 보고, 책별 발췌 수·깨짐 수·교정 낱말 수·표 표시 수와 표를 뺀 이유를 `data/reading-audit.json`에 기록합니다.

전체 자료 재처리는 `python scripts/rebuild_passages.py`, 검사는 `python scripts/audit_passages.py`입니다. `data/full-text-audit.json`은 26권 12,147페이지의 처리 누락·공백 외 글자 변경·문단 유형과 문법/독서/작문/문학 35개 질의의 실제 발췌·순위·시간을 기록합니다. 자동 전수 검사는 모든 OCR 글자의 정확성이나 모든 질문의 관련성을 보증하는 수동 검수가 아닙니다.

본문 처리 구현은 `text_pipeline.py`와 `passage_text.py`, 검색은 `retrieval.py`와 `passage_search.py`, 뜻으로 찾기는 `vector_search.py`(색인 생성 `scripts/build_vectors.py`), 벡터 색인이 없을 때의 로컬 의미 비교는 `local_semantics.py`입니다. 오인식 의심 문장은 대표 발췌에서 제외하며, 원래 추출문은 출처 창에서 열 수 있습니다. 띄어쓰기 자동 정리는 글자 오인식 교정과 별개입니다.

앱 우측 상단의 **연결 설정**에 직접 입력합니다. 브라우저는 localhost 서버로만 키를 보내고 입력란을 즉시 비웁니다. 키는 이 컴퓨터의 .env 파일에 저장하며 다음 실행부터 자동 연결합니다. API 응답·URL·로그·브라우저 저장소·서비스워커 캐시에 넣지 않습니다. 연결 설정의 저장된 키 삭제 버튼으로 제거할 수 있습니다. 실제 API 사용 가능 여부는 첫 해설 요청에서 확인합니다.

선택적으로 `.env.example`을 `.env`로 복사해 로컬 파일에 설정할 수도 있습니다. 이 방식은 디스크에 키가 남습니다. `.env`는 Git 제외 대상이고 웹 서버가 제공하지 않습니다. 공개 서버에서는 이 파일을 읽지 않으며 화면의 키 입력도 비활성화됩니다(아래 공개 배포 참고).

`.env`는 저장할 때 Windows에서 현재 사용자·SYSTEM·관리자만 접근하도록 ACL을 제한합니다. 키는 여전히 로컬 디스크와 실행 중인 서버 메모리에 존재하므로, 해당 계정이나 관리자 권한이 침해된 상황까지 방어하지는 못합니다.

## 공개 배포 (Firebase Hosting + Cloud Run + Firestore)

로컬 실행(`start.cmd`)과 공개 서버는 같은 코드이며, 환경변수 `PUBLIC=1`(Dockerfile이 설정)일 때만 공개 모드로 동작합니다.

- **공개 모드의 차이**: 모든 주소에 바인딩하고 localhost Host 검사를 끕니다. POST는 `Sec-Fetch-Site: same-origin`이거나 Origin의 호스트가 요청의 Host·`X-Forwarded-Host`·`ALLOWED_HOSTS`(쉼표 구분) 중 하나와 같을 때만 허용합니다. `/api/key`는 404를 돌려주고 키는 환경변수 `OPENAI_API_KEY`에서만 읽습니다. `.env` 파일은 읽지 않습니다. 쪽수 대조·재OCR은 관리자 전용입니다.
- **로그인 없음, 서재 전체 하루 100회**: AI 해설이 필요한 요청은 방문자를 구분하지 않고 서버 전체로 하루 100회까지 허용합니다(`DAILY_TOTAL`로 조정). 한국 시각 자정에 초기화되고, 남은 횟수는 화면 왼쪽과 해설 버튼 옆에 적어 둡니다. 초과하면 해설 없이 원문 검색·개념 정리·찾아보기 결과만 돌려주고 안내문을 붙입니다. 해설 생성이 실패하면 횟수를 돌려줍니다. 1인당 배분이 없으므로 한 사람이 하루치를 모두 쓸 수도 있습니다. 전체 상한과 OpenAI 프로젝트의 월 예산 한도가 실제 방어선입니다. 방문자 식별을 하지 않으므로 쿠키도 심지 않습니다.
- **횟수 저장소**: `QUOTA_BACKEND`가 `firestore`(공개 모드 기본)면 Google Cloud Firestore의 `quota_daily` 컬렉션에 날짜별 문서 하나로 기록합니다. Cloud Run에서는 별도 키 파일 없이 기본 서비스 계정으로 접근합니다. 문서에는 `expires` 필드가 있어 Firestore TTL 정책을 걸면 자동 삭제됩니다. Firestore에 연결하지 못하면 해설을 거부하고 검색만 제공합니다(fail closed). `memory`는 프로세스 메모리에만 세는 시험용, `none`(로컬 기본)은 세지 않습니다.
- **관리자**: 환경변수 `ADMIN_TOKEN`과 같은 값을 `X-Admin-Token` 헤더로 보내면 횟수 제한 없이 해설을 생성하고 쪽수 대조도 할 수 있습니다. 화면 우측 상단 **관리자** 단추에서 토큰을 입력하면 그 브라우저의 localStorage에만 저장합니다. 토큰이 틀리면 저장하지 않습니다.
- **자료는 버킷에, 배포는 어디서나**: `data/`(발췌 DB 276MB, BGE-M3 질의 모델 570MB·벡터 색인 121MB, E5 모델 137MB, 쪽별 원문 53MB)는 git에 없고 같은 프로젝트의 Cloud Storage 버킷에 둡니다. `python scripts/cloud.py push-data`로 올리고(Windows에서는 gcloud가 제외 규칙을 백슬래시 경로에 맨 앞부터 적용하므로 `SYNC_EXCLUDE`가 두 구분자를 모두 받습니다), 다른 컴퓨터에서는 `git pull` 뒤 `pull-data`로 받습니다. 배포(`deploy`)는 코드만 올리고 Cloud Build가 버킷에서 `data/`를 받아 이미지에 넣으므로(`cloudbuild.yaml`) 자료가 없는 컴퓨터에서도 됩니다. 설정은 `deploy.json`(프로젝트 ID·리전·서비스명·버킷명)입니다. `개론서 파일/`, `.runtime/`, `.env`, `tests/`는 이미지에 들어가지 않습니다. 개념 JSON도 서버가 읽으므로 개념을 고치면 다시 `deploy`해야 합니다.
- **명령**: 프로젝트마다 한 번 `python scripts/cloud.py setup`(API 활성화, 버킷·이미지 저장소 생성). 첫 배포는 `python scripts/cloud.py deploy --openai-key ... --admin-token ...`, 이후에는 `python scripts/cloud.py deploy`만 실행하면 이전 환경변수를 유지합니다. Firebase Hosting은 `dist/`를 서비스하고 `/api/**`를 이 Cloud Run 서비스로 넘깁니다(`firebase.json`, `firebase deploy --only hosting`).
- **다른 컴퓨터에서 이어서 작업**: `git clone` 또는 `pull` → `python -m pip install -r requirements.txt` → `gcloud init`과 `firebase login`(컴퓨터마다 한 번) → 로컬 실행이 필요하면 `python scripts/cloud.py pull-data`. 배포만 할 거면 `pull-data` 없이 `deploy`가 됩니다. 자료를 다시 처리한 컴퓨터에서는 `push-data`로 버킷을 갱신합니다.
- **메모리 4Gi**: 서버는 시작하면서 BGE-M3 int8 질의 모델과 벡터 색인을 올립니다. Windows에서는 검색 뒤 약 1.1GB였지만 Cloud Run(Linux)에서는 2Gi를 넘겨 검색 요청마다 인스턴스가 종료되었습니다(`Memory limit of 2048 MiB exceeded`). 그래서 `deploy.json`의 `memory`를 `4Gi`로 올렸고, 이때 사용률은 약 55%(2.2~2.3GiB)이며 동시 검색 6건도 오류 없이 처리했습니다. E5만 쓰던 이전 리비전은 2Gi의 21%(약 430MiB)였습니다. CPU가 1개라 검색이 동시에 몰리면 한 건당 5~12초로 느려집니다.
- **남는 위험**: 방문자는 키 문자열을 볼 수 없지만 하루 100회 범위에서 키의 크레딧을 씁니다. 1인당 제한이 없어 한 사람이나 자동화된 요청이 하루치를 빠르게 소진할 수 있습니다. 배포 키는 이 앱 전용 OpenAI 프로젝트에서 발급하고 예산 한도를 걸어 두세요. 감사 로그는 Cloud Run 로그의 오류 줄 외에는 남기지 않습니다.
- `.env`, `data/`, `개론서 파일/`은 `.gitignore`에서 제외합니다. 새 저장소를 만든 뒤 첫 커밋 전 실제 스테이징 목록과 비밀 탐지 결과를 다시 확인해야 합니다.

자동 테스트는 OpenAI 응답을 대체하여 검색 확장, 구조화된 설명·표, 인용 검사, 검색 시 API 미호출, 오류 처리를 검증합니다. 8766 고정 응답 화면은 폐기했습니다. 이전 주소는 실제 앱(8765)으로 이동하며 질문 API는 410을 반환합니다. `python scripts/verify_explanation.py --live`는 실제 질문·관련 원문을 기존 설정된 OpenAI API로 보내는 별도 검증입니다. 실제 해설 검증은 사용자가 허용한 대표 질문과 관련 발췌문에 한해 실행하며, `data/explanation-verification-*.json`에 질문별 결과를 저장합니다. 이 파일을 서버의 답변으로 재생하지 않습니다.

## OCR와 쪽수 정확도

기존 PDF의 OCR 텍스트를 페이지별로 추출해 `data/text/<book-id>/<PDF페이지>.json`에 보존합니다. 빈 텍스트 또는 글자가 적은 페이지는 Tesseract 한국어·영어 OCR로 보완하고 `.ocr.json`으로 별도 저장합니다. 글자 수는 충분하지만 내장 텍스트가 심하게 깨진 페이지는 `scripts/repair_noisy_ocr.py`가 Kiwi 언어 모델의 글자당 점수로 가려내어 300dpi로 다시 OCR하고, 점수가 뚜렷이 높아질 때만 새 텍스트를 채택합니다. 이때 행 좌표도 함께 저장해 문단 분리에 씁니다. 다시 OCR한 뒤에도 점수가 낮은 페이지(표·시·음운 기호·앞표지 등 산문이 아닌 쪽 포함)는 `quality='review'`로 두어 검색 순위를 낮추고 화면에 원문 이미지 대조가 필요하다고 표시합니다. 점수는 `page_quality` 표에 남기며 `--remark`로 OCR 없이 기준만 다시 적용할 수 있습니다. SQLite에는 현재 검색할 텍스트와 추출 방식이 저장됩니다. 원본 PDF는 수정하지 않습니다.

책 쪽수는 페이지 여백에서 직접 읽은 숫자가 앞뒤 페이지 번호와 일치할 때 `sequence`, 사람이 원문과 대조했을 때 `manual`, **앞뒤로 확정된 두 쪽이 같은 간격을 가질 때 그 사이를 계산해 채운 경우 `offset`**으로 관리합니다(7,819 → 11,357쪽 / 전체 12,787쪽). `offset`은 화면에 **책 N쪽(계산)**으로 적고 출처 창에 "여백에서 읽지 못해 앞뒤 확정 쪽의 간격으로 계산"이라고 밝힙니다. 확정된 구간의 **바깥**은 채우지 않습니다 — 앞부분 별면은 쪽 매김이 다르고 어디서 끝나는지 글자층이 말해 주지 않기 때문입니다. 채운 구간 안에서 여백 숫자가 읽히는 자리 1,723곳과 대조해 1,581곳이 일치했고, 어긋난 142곳은 잘려 읽힌 숫자(130을 13으로, 141을 1로)이거나 쪽번호가 아닌 숫자(연도 1965, 차례 항목)였습니다. 한 구간에서 **다른 간격으로 세 쪽 이상이 맞아떨어지는 경우는 0곳**이었습니다 — 실제로 쪽 매김이 바뀌면 그렇게 나타납니다. 그래도 확정되지 않은 1,430쪽은 **자료 N페이지 · 책 쪽수 미확인**으로 표시하며 PDF 순번을 책 쪽수로 바꿔 쓰지 않습니다(시와 함께 배우는 시는 확정된 쪽이 하나도 없어 385쪽 전부가 여기 속합니다). 다시 실행: `python scripts/verify_numbers.py`. 전체 페이지의 OCR 교정·인쇄 쪽수 검수는 완료를 보장하지 않습니다. 옛한글, 음운 기호, 표, 각주, 다단 편집은 특히 오인식이 있을 수 있습니다.
